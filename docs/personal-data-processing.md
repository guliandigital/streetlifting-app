# Обработка персональных данных: текущее состояние и предложения

Дата: 2026-09-19. Составлено по коду ветки `claude/project-analysis-2c13f0` (после переезда на
Vercel). Это инженерная инвентаризация, а не юридическое заключение: выводы по 152-ФЗ нужно
подтвердить у юриста до массового хранения данных граждан РФ.

## 1. Какие данные обрабатываются

Последующее дополнение: [контроль доступа к фото](athlete-photo-privacy.md)
реализован локально. Ниже описана исходная уязвимость до исправления; production
пока не проверен и не обновлён в рамках этой работы.

Дополнение 2026-09-19: локально продолжен срез «оператор в согласии + подтверждение
допуска + организатор турнира». Его поведение, проверки и ограничения выпуска
описаны в [personal-data-access-slice.md](personal-data-access-slice.md). Ниже
сохранены исходные результаты аудита; пункты про прежние короткие тексты относятся
к состоянию до этого среза. Миграция и production-выпуск не выполнены.

| Категория                | Поля                                                                                                                                          | Где                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Спортсмены               | ФИО, дата рождения, пол, страна/регион/город, клуб, тренер, номер карточки федерации, фото, вес на взвешивании, попытки и результаты, разряды | `athlete`, `nomination`, `attempt`, `record`, `sport_rank_award`, Blob |
| Пользователи (аккаунты)  | e-mail, телефон, Telegram, отображаемое имя, argon2-хэш пароля, ISF ID subject                                                                | `user`, `external_identity_link`                                       |
| Судьи / официальные лица | ФИО, категория, номер удостоверения, город, документы-подтверждения (файлы)                                                                   | `judge`, `official_profile`, `official_credential`, Blob               |
| Федерации                | контактные телефон/e-mail/Telegram, ФИО бухгалтера и кассира, платёжные документы                                                             | `federation`, `receipt`, `writeoff`, Blob                              |
| Паспорт спортсмена       | вложения (сертификаты, удостоверения, «прочее»), заявки на проверку                                                                           | `attachment`, `passport_review_request`                                |

Специальных категорий (здоровье и т. п.) нет; вес тела и год рождения — обычные ПД.

## 2. Как устроено сейчас

### Согласия

- Модель `consent`: scope (`data_processing`, `public_results`, `photo_publication`,
  `marketing_email`, `marketing_telegram`), показанный текст, локаль, версия текста, время, IP,
  User-Agent, отзыв (`revokedAt`, причина). Отзыв — `POST /passport/consents/:id/revoke`, с
  аудитом `passport.consent.revoked`.
- Публичная регистрация фиксирует три согласия с версией `2026-05-11.v1`. **Тексты — на
  английском, одной строкой** («I consent to personal data processing for participation in the
  competition») и не содержат обязательных для 152-ФЗ реквизитов: оператор, цели, состав данных,
  срок, порядок отзыва. Маркетинговые scope в коде объявлены, но нигде не собираются.
- Вложения паспорта и заявки на проверку загружаются без отдельного согласия на обработку
  документов.

### Публичное раскрытие

- `GET /public/competitions/:id/scoreboard` без авторизации отдаёт по каждому участнику **полное
  ФИО, год рождения, клуб, вес на взвешивании, фото, результаты и места**. Режим
  `athlete.privacyMode = hidden` скрывает только год рождения и фото; ФИО и вес остаются.
  Федерация может закрыть публичные результаты целиком (`isPublicResultsClosed`).
- `GET /athletes/:id/photo` — публичный эндпоинт без авторизации (нужен для `<img>`). Он **не
  проверяет** ни `photo_publication`, ни `privacyMode`: скрытый режим убирает ссылку из табло, но
  сам файл доступен любому, кто знает `id` спортсмена.
- ISF-экспорт защищён allowlist'ом (`privacy-allowlist.ts`): дата рождения, контакты, платежи,
  согласия, хэши в него попасть не могут; это покрыто тестами.

### Минимизация в логах и телеметрии

- pino: список `REDACT_PATHS` вырезает пароли, токены, e-mail, телефон, дату рождения.
- Sentry: `sendDefaultPii: false`, `beforeSend` чистит заголовки, cookie, e-mail, IP, поля тела.
  DSN в продакшене пока не задан.
- Vercel request logs содержат IP клиента (стандартный формат платформы); log drains не настроены.

### Доступ и аудит

- RBAC-матрица (`authorization-matrix.ts`) с тестами; все приватные маршруты по умолчанию
  закрыты.
- `audit_log` — append-only, с IP/UA актора и снимками до/после для привилегированных записей.

### Хранение и локализация (после переезда)

| ------------------------ | ----------------------------- | ---------------------------------------------------------- |

### Сроки хранения и права субъекта

- Сроков хранения нет ни для чего: refresh-токены (с IP/UA), записи аудита, отозванные согласия и
  профили хранятся бессрочно; фоновой очистки нет.
- Нет экспорта данных субъекта, нет удаления/анонимизации аккаунта или спортсмена по запросу;
  есть только отзыв согласия и отключение публикации результатов.
- Нет опубликованной политики обработки ПД, уведомления в РКН (`security-checklist.md`, M9),
  реестра обработок и договоров с обработчиками (Vercel, Neon).

## 3. Что это означает по 152-ФЗ

- **Локализация (ст. 18 ч. 5).** Запись, систематизация, накопление, хранение, уточнение и
  извлечение ПД граждан РФ должны выполняться с использованием баз данных на территории РФ.
  Первичная база в Neon (ЕС/США) этому требованию не соответствует. Спортсмены из Армении,
  Казахстана и иностранные участники ISF под это требование не подпадают, но приложение
  RU-first.
- **Трансграничная передача (ст. 12).** С 1 марта 2023 года требуется уведомление РКН до начала
  передачи; для стран без «адекватной защиты» (в том числе США) — дополнительные условия.
  Обработка в памяти функций Vercel за рубежом — уже передача.
- **Уведомление об обработке (ст. 22)** и **политика (ст. 18.1)** — обязательны для оператора.
- **Роли.** Нужно зафиксировать, кто оператор: федерации (собирают данные своих спортсменов), а
  ИП Гулян А. Г. — обработчик по поручению (ст. 6 ч. 3), либо ИП — оператор платформы. От этого
  зависят тексты согласий, договоры с федерациями и содержание уведомления в РКН.
- Штрафы за нарушение локализации (КоАП 13.11 ч. 8–9) — миллионы рублей для юрлиц; для ИП
  меньше, но с блокировкой ресурса по решению суда.

## 4. Предложение

### 4.1 Архитектура: вычисления на Vercel, данные в РФ (рекомендую)

Оставить web и функции на Vercel, а «первичную базу» и файлы разместить в России:

| Компонент      | Сейчас               | Предложение                                                                                                                                                                                                                   |
| -------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Postgres       | Neon (ЕС/США)        | Managed PostgreSQL в РФ (Yandex Cloud, Selectel, VK Cloud) или Postgres на существующем reg.ru VPS с TLS и allowlist по IP; `DATABASE_URL` в Vercel указывает на него. Neon — только для preview/dev с синтетическими данными |
| Файлы          | Vercel Blob (`fra1`) | S3-совместимое хранилище в РФ (Yandex Object Storage / Selectel); в `storage.ts` добавить драйвер `s3` (третий, рядом с `fs` и `vercel-blob`)                                                                                 |
| Регион функций | `iad1` (США)         | `fra1` (Франкфурт): ~40 мс до Москвы вместо ~120, страна ЕС                                                                                                                                                                   |
| Sentry         | не включён           | при включении — регион EU или self-hosted; PII уже вычищается                                                                                                                                                                 |

Это распространённая конфигурация «первичная БД в РФ, обработка за рубежом»; она требует
уведомления РКН о трансграничной передаче и подтверждения юристом. Полный отказ от Vercel
(всё в РФ) — запасной вариант, если юрист не примет эту схему.

Стоимость реализации: драйвер S3 (~150 строк + тесты), смена `DATABASE_URL`, регион в
`vercel.json`. Код приложения больше не меняется — слой хранилища уже абстрагирован.

### 4.2 Продукт и код (не зависят от хостинга)

1. **Согласия.** Русские полнотекстовые версии (оператор, цели, состав, срок, порядок отзыва),
   ссылка на политику, новая `textVersion`; галочки не предзаполнены; отдельное согласие на
   загрузку документов в паспорте; для несовершеннолетних — согласие законного представителя
   (в стритлифтинге есть юниорские категории — сейчас это никак не отражено).
2. **Фото.** `GET /athletes/:id/photo` должен отдавать файл только при активном
   `photo_publication` и `privacyMode !== 'hidden'`; иначе 404. Альтернатива — подписанные
   короткоживущие URL.
3. **Публичное табло.** Ввести уровень раскрытия на федерацию/соревнование: по умолчанию ФИО
   полностью (спортивный протокол), в режиме `hidden` — фамилия и инициалы, без клуба. Вес на
   взвешивании публиковать только там, где это требуется регламентом (весовые категории и так
   видны).
4. **Права субъекта в кабинете.** Экспорт своих данных (JSON/PDF), удаление аккаунта с
   анонимизацией: контакты и фото удаляются, результаты в протоколах остаются под
   анонимизированным ФИО (законный интерес федерации в целостности протокола) или полным ФИО
   по решению юриста.
5. **Сроки хранения** (cron на Vercel, как для ISF outbox): истёкшие refresh-токены — сразу после
   истечения; отозванные согласия — 3 года после отзыва (доказательство); аудит — 3 года;
   заявки паспорта без движения — 1 год; IP/UA в согласиях — вместе с согласием.
6. **Логи.** Не включать log drains с телом запросов; при подключении Sentry — EU-регион.
7. **Уведомления.** Реестр обработок и сроков — в `docs/`, чтобы политика и уведомление в РКН
   опирались на факты из кода.

### 4.3 Документы и организация

1. Решение о ролях (оператор/обработчик) и типовой договор-поручение с федерациями.
2. Политика обработки ПД на `streetlifting.app` (ст. 18.1) и пользовательское соглашение.
3. Уведомление в РКН об обработке (ст. 22) и о трансграничной передаче (ст. 12).
4. DPA/договоры с обработчиками: Vercel, провайдер БД/S3 в РФ, mail.ru (почта), Sentry.
5. Ответственный за организацию обработки ПД (ст. 18.1 ч. 1 п. 1) и порядок ответа на
   запросы субъектов (10 рабочих дней).

## 5. Порядок внедрения

1. Юридическое решение по архитектуре (4.1) и ролям (4.3.1) — до переключения DNS на Vercel
   для продакшена с реальными данными.
2. Код: фото-эндпоинт с проверкой согласия, русские тексты согласий, драйвер S3 — один слайс.
3. Кабинет: экспорт и удаление; cron очистки — второй слайс.
4. Политика, уведомления РКН, договоры — параллельно с 2–3.
