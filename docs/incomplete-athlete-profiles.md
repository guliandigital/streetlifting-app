# Неполные профили спортсменов

Публичные исторические протоколы могут содержать только год рождения и не указывать страну спортсмена. Такие сведения сохраняются без выдуманной даты 1 января или национальности федерации.

- `Athlete.birthYear`: nullable integer, 1900–2100.
- `dateOfBirth` и `countryCode` допускают null. Существующие значения миграция не изменяет.
- Администратор создаёт и дополняет профиль через карточку. Полная дата задаёт соответствующий год; противоречивый год отклоняется API и ограничением БД. При очистке даты API сохраняет известный год, если год явно не очищен.
- Публичная регистрация по-прежнему требует полную дату и страну. Подтверждение мандатной комиссии для неполного профиля отклоняется с `athlete_profile_incomplete`.
- Архивные результаты могут ссылаться на неполный профиль. Это не подтверждает возрастной допуск, согласие на публикацию фото или присвоение разряда.
- В интерфейсе выводится год без вычисленного точного возраста. Экспорт ISF сохраняет только год; для `hidden` год не раскрывается. Неизвестная страна экспортируется как null. Потребители `isf.export.v1` должны принимать nullable `countryCode` у спортсмена; страна федерации остаётся обязательной.

## Выпуск

Сначала применить миграцию `20260919180000_incomplete_athlete_profiles`, затем выпустить API и web. Создавать неполные записи только после проверки обоих приложений. Возврат к старому приложению после появления null-полей небезопасен; исправлять выпуск вперёд, не подставлять фиктивные данные.

Импорт PowerTable должен сопоставлять устойчивый source athlete ID и сохранять источник. Двузначный год, неизвестная дисциплина, неоднозначная личность и агрегированные таблицы требуют отдельной проверки; поддержка null не делает эти записи автоматически подтверждёнными.

## Проверки

`pnpm release:check` — схемы, типы, lint, тесты и сборки.
`pnpm check:personal-data:db --run --browser-all` — изолированные PostgreSQL fresh/upgrade, API-проверки согласий/профиля/допуска и браузерное создание/дополнение профиля.
