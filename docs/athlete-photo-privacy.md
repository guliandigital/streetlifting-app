# Доступ к фотографиям спортсменов

Локальная реализация от 2026-09-19, без миграций и deployment.

## Поведение

- Публичный `GET /athletes/:id/photo?federationId=...` требует активного
  `photo_publication` именно этой федерации, открытых публичных результатов
  федерации и `privacyMode != hidden`. Без параметра применимо только отдельное
  глобальное согласие (`federationId = null`). Согласие другой федерации не подходит.
- Нет спортсмена, согласия или доступа — 404 до чтения файлового хранилища.
  HEAD имеет тот же контроль. Некорректная федерация — 400, невалидный переданный
  Bearer — 401, чтобы приватный клиент мог обновить токен.
- Приватный доступ без разрешения на публикацию остаётся у владельца профиля,
  администратора платформы и активных ролей `LIVE_OPS_READ_ROLES`, если спортсмен
  имеет заявку в соревновании соответствующего scope. Роль без scope или только
  в `pendingAcknowledgments` доступа не даёт. Это правило относится к фото,
  не является аудитом всех остальных endpoints спортсменов/вложений.
- Карточка спортсмена использует существующий `requestBlob` с Bearer, показывает
  временный blob URL и освобождает его при смене профиля/пользователя/размонтировании.
  При ошибке нет перехода на неавторизованный URL.
- Общее скачивание вложений не выдаёт `athlete_photo`: фото доступно только через
  специализированный endpoint. Знание ID вложения не обходит проверку.
- Публичное табло возвращает URL фото только при активном согласии своей федерации;
  URL содержит этот scope. Hidden-профили не получают URL даже при согласии.
- Фото и публичное табло отвечают `private, no-store`; выдача фото также содержит
  `Vary: Authorization`. Отзыв проверяется при каждом новом запросе. Уже загруженные
  изображения отозвать из памяти клиента нельзя; старые ответы до выпуска могли
  кэшироваться до 300 секунд.

## Проверки

- `athletes.photo.test.ts`: 19 тестов, включая scoped/global consent, отзыв,
  hidden, закрытую федерацию, HEAD, чужие роли и обход через attachment download.
- `route-authorization.test.ts`: 11 тестов, включая три сценария фото на табло.
- `athlete-photo-privacy.spec.ts`: браузер Edge, замоканный API, Bearer и blob URL.
- API/web typecheck, E2E typecheck, lint затронутых файлов и сборки API/web пройдены.

Дополнительно пройдена [интеграционная проверка с реальной БД](personal-data-db-check.md)
и файловым хранилищем, включая отзыв роли и согласия. Пройден браузерный E2E
с настоящим API: регистрация без согласия на фото, загрузка администратором,
публичный 404 и приватное изображение в карточке (проверены blob URL и naturalWidth).
Фактический deployment не проверен. Схема БД для фото не менялась.
Миграция допуска проверена только на изолированной БД, к рабочим БД не применялась.
API и web выпускаются согласованно:
старый web загружает фото обычным img без Bearer и без scope федерации.

## Вне этого среза

Изменение ФИО/клуба/веса на публичном табло, общая модель публикации результатов,
magic-byte проверка загрузок, права на прочие вложения, retention и юридические
документы не реализованы здесь.
